# Деплой на VPS

Инструкция рассчитана на VPS, где уже могут крутиться другие проекты (nginx/другие
контейнеры, занятые порты 80/443). Все шаги — команды, которые выполняешь сам на сервере
по SSH.

## 0. Перед началом — посмотри, что уже занято

```bash
sudo ss -tlnp
docker ps
```
Обрати внимание, свободны ли порты `8001`, `8002` (наши сервисы) и `80`/`443` (если будешь
вешать домен через reverse proxy). Если что-то занято — поменяешь порты в
`docker-compose.yml` под себя (см. шаг 4).

## 1. Docker на сервере

Проверь, стоит ли уже:
```bash
docker --version
docker compose version
```
Если нет — официальный скрипт-установщик (Ubuntu/Debian):
```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```
После `usermod` — перелогинься (`exit` и зайди по SSH заново), иначе `docker` без `sudo`
не заработает.

## 2. Забрать код

```bash
git clone <URL-твоего-репозитория> task-user-service
cd task-user-service
```
Если репозиторий приватный — на сервере нужен SSH-ключ, добавленный в GitHub (deploy key),
либо клонируй по HTTPS с personal access token.

## 3. `.env` — секреты для прода

**Не копируй свой локальный `.env`** — он не в git (проверил `.gitignore`), и в нём,
скорее всего, dev-значения. Создай новый на сервере из шаблона:
```bash
cp .env.example .env
nano .env
```
Обязательно поменяй (шаблон это подсвечивает как `change-me`):
- `USER_DB_PASSWORD`, `TASK_DB_PASSWORD` — пароли БД
- `ADMIN_BOOTSTRAP_SECRET` — секрет для создания первого админа
- `JWT_SECRET_KEY` — секрет для подписи токенов, **обязательно длинный и случайный**

Сгенерировать случайное значение:
```bash
openssl rand -hex 32
```

## 4. Порты — если 8001/8002 заняты другим проектом

В базовом `docker-compose.yml` порты уже привязаны только к `127.0.0.1` (не наружу):
```yaml
ports:
  - "127.0.0.1:8001:8000"   # user-service
  - "127.0.0.1:8002:8000"   # task-service
```
Это уже безопасно по умолчанию — сервисы недоступны из интернета напрямую, только с самого
сервера. Если `8001`/`8002` заняты другим проектом — поменяй левую часть на свободные,
например `127.0.0.1:8011:8000`.

## 5. ⚠️ Критично — НЕ используй `docker-compose.override.yml` на сервере

Этот файл — только для локальной разработки (live-reload, БД/Kafka наружу для
удобства отладки). Если он случайно применится на проде — Postgres и Redpanda станут
доступны всему интернету без файрвола, порты `5433`/`5434`/`9092`/`8082` там указаны без
привязки к `127.0.0.1`, то есть биндятся на `0.0.0.0`.

Docker Compose **автоматически подхватывает** `docker-compose.override.yml`, если он лежит
рядом, даже без явного указания. Поэтому на сервере — либо:

**Вариант А (проще и надёжнее) — не давать ему примениться:**
```bash
rm docker-compose.override.yml
```

**Вариант Б — оставить файл, но всегда явно указывать, какой конфиг использовать:**
```bash
docker compose -f docker-compose.yml up -d --build
```
(добавь такой алиас/скрипт себе, чтобы не забыть флаг `-f` при каждом деплое)

## 6. Поднять стек

```bash
docker compose -f docker-compose.yml up -d --build
```
Миграции (`alembic upgrade head`) выполняются автоматически при старте `task-service` и
`user-service` — отдельно накатывать не нужно, это уже часть `CMD` в их `Dockerfile`.

Проверить, что всё поднялось:
```bash
docker compose ps
curl http://127.0.0.1:8001/health
curl http://127.0.0.1:8002/health
```

## 7. Автозапуск при перезагрузке сервера

В `docker-compose.yml` сейчас **нет** политики рестарта — после перезагрузки VPS
контейнеры сами не поднимутся. Добавь в каждый сервис `restart: unless-stopped`
(это отдельная правка, которую стоит внести перед первым продовым деплоем — спроси,
если хочешь, чтобы это сделал я).

## 8. Домен и HTTPS (если нужен внешний доступ, не просто по IP)

Раз на сервере уже что-то крутится — скорее всего, уже есть reverse proxy (nginx/Caddy),
который слушает 80/443. Смотри, как проксируются существующие сайты (`nginx -T` или
конфиги в `/etc/nginx/sites-enabled/`), и добавь по тому же образцу новый
server-блок/домен, указывающий на `127.0.0.1:8001` и `127.0.0.1:8002`. Если reverse proxy
ещё нет — проще всего поднять **Caddy** (автоматический Let's Encrypt, минимум конфига)
отдельным контейнером или systemd-сервисом, а не городить nginx+certbot руками.

## 9. Firewall

Открой наружу только то, что реально должно быть публичным:
```bash
sudo ufw allow OpenSSH
sudo ufw allow 80,443/tcp
sudo ufw enable
```
Порты `5433`, `5434`, `9092`, `8082`, `8090` открывать наружу не нужно — они и так не
проброшены наружу в базовом `docker-compose.yml` (см. шаг 5), просто не открывай их
дополнительно вручную.

## Дальнейшие обновления

```bash
cd task-user-service
git pull
docker compose -f docker-compose.yml up -d --build
```
